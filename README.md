# Knowledge Distillation for Small Language Models: From Instruction Following to Sub-Quadratic Attention

Code and configurations for the master's thesis of Lukas Rosenberger,
Institute for Machine Learning, Johannes Kepler University Linz (2026).

The thesis asks what knowledge distillation transfers to a smaller or more
efficient student, and what decides what transfers. It studies two settings:

- **Setting A** distills an instruction-tuned teacher (Qwen3-4B-Instruct-2507)
  into a pretrained base student of the same family (Qwen3-0.6B-Base).
- **Setting B** converts AFM-4.5B-Base into students whose softmax attention
  layers are replaced by Kimi Delta Attention (KDA) or Gated DeltaNet (GDN), in
  a 3:1 hybrid or an all-linear layout, and distills the teacher into them in
  two stages (stage 1 on FineWeb-Edu, stage 2 on FineWeb-Edu or FineMath).

All training uses online logit distillation with a fork of
[DistillKit](https://github.com/arcee-ai/DistillKit).

## Repository layout

| folder | contents |
|---|---|
| `DistillKit/` | the DistillKit library as used, with two small changes (see `DistillKit/MODIFICATIONS.md`) |
| `afm_kda/` | the Setting B student model: `AFMKDAForCausalLM`, a subclass of the Hugging Face Arcee model with KDA or GDN token mixers, NoPE attention layers with an output gate, and a recurrent cache for generation |
| `building_students/` | building a student from the teacher (`build_student.py`), finalizing a trained checkpoint for evaluation (`finalize_checkpoint.py`) |
| `data_preparation/` | download and splits of FineWeb-Edu and FineMath (held-out, stage 1, stage 2) |
| `run_configurations/` | every training configuration (DistillKit YAML) and its SLURM script; `setting_a/` holds Setting A |
| `evaluations/` | benchmarks (LM Evaluation Harness), arithmetic probe, held-out KL, decay-value analysis, speed and memory benchmark, plots and tables of the thesis |
| `tests/` | the checks run while building the students (e.g. the all-attention student reproduces the teacher exactly, cached generation equals full recomputation) |
| `env/` | the Python environments |

## Runs and their configurations

Each training YAML in `run_configurations/` has an SLURM script of the same
name. Every Setting B run used 4 nodes with 4 A100 GPUs each.

| thesis name | run | stage 1 | stage 2, FineWeb-Edu | stage 2, FineMath |
|---|---|---|---|---|
| KDA hybrid | R1 | `r1_stage1_4node.yaml` | `r1_stage2_kda_hybrid31_unfreeze.yaml` | `r1_stage2_finemath.yaml` |
| GDN hybrid | R2 | `r2_stage1_*.yaml` | `r2_stage2_gdn_hybrid31_unfreeze.yaml` | `r2_stage2_gdn_hybrid31_finemath.yaml` |
| KDA all-linear | R3 | `r3_stage1_*.yaml` | `r3_stage2_kda_only_unfreeze.yaml` | `r3_stage2_kda_only_finemath.yaml` |
| GDN all-linear | R4 | `r4_stage1_*.yaml` | `r4_stage2_gdn_only_unfreeze.yaml` | `r4_stage2_gdn_only_finemath.yaml` |
| GDN with KDA's output gate | R6 | `o2_stage1.yaml` | `o2_stage2.yaml` | – |

## Reproducing a Setting B run

All scripts were run on the Leonardo supercomputer (CINECA). Paths in the
scripts point to `/leonardo_work/...`; set `WORK_LUKAS` and the paths in the
YAML and SLURM files to your own directories. Run Python scripts from the
repository root with `PYTHONPATH=.` so that `afm_kda` can be imported.

1. **Environment.** See `env/`. The flash-linear-attention version is pinned
   to 0.5.2 on purpose: later versions handle `cu_seqlens` differently.
2. **Data.** Download and split FineWeb-Edu and FineMath with the scripts in
   `data_preparation/`.
3. **Student.** Build the untrained student from the teacher, e.g.
   `PYTHONPATH=. python building_students/build_student.py --variant hybrid31`
   (variants: `hybrid31`, `only`, `gdn_hybrid31`, `gdn_only`). The build copies
   the teacher's embeddings, norms and MLPs, transfers the attention projections
   into the new layers and records a `build_info.json` with the parameter
   count and the git commit.
4. **Training.** Submit the stage-1 SLURM script, then stage 2 from the final
   stage-1 checkpoint (`accelerate` + DeepSpeed ZeRO stage 2).
5. **Evaluation.** Run `building_students/finalize_checkpoint.py` on the trained
   checkpoint (it checks the model code and enables the cache), then the
   scripts in `evaluations/`.

Every checkpoint carries its own copy of the model code and loads with
`AutoModelForCausalLM.from_pretrained(path, trust_remote_code=True)`.
